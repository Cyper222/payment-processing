## Проверенные сценарии

- POST / GET, обязательные заголовки, 401 / 404 / 409 / 422 / 503, защита документации и health.
- Нормализация суммы, десять конкурентных запросов с одним ключом, единственный Payment и Outbox.
- Ошибка INSERT в Outbox откатывает Payment целиком.
- Недоступный publisher оставляет событие неопубликованным; восстановление возобновляет публикацию.
- Сбой после publisher confirm до commit `published_at` вызывает повторную публикацию, но не повторную оплату.
- Конкурентные dispatcher используют SKIP LOCKED и не блокируют друг друга на одной записи.
- Бизнес-отказ, конкурентные дубли, запись результата до webhook, отмена процесса и возобновление webhook.
- Потеря соединения PostgreSQL не позволяет записать прогресс через новое соединение без прежней advisory-блокировки.
- Три webhook-попытки, durable retry в Outbox, реальные TTL 2 / 4 секунды, DLQ и диагностические данные.
- Mandatory publish без маршрута возвращает ошибку; успешная обработка подтверждает исходное сообщение.
- При ошибке републикации quorum delivery limit ограничивает аварийные redelivery.
- Ручной replay сохраняет результат оплаты и игнорирует запоздалые сообщения старого цикла.
- Webhook: 2xx, ошибки транспорта и HTTP, timeout, SSRF, DNS pinning, HMAC, стабильный идентификатор.

## Проверки запущенного сервиса

`scripts/smoke.py` успешно прошёл на итоговом runtime-образе:

- успешный webhook: `200`;
- временный сбой: `503 → 503 → 200`;
- постоянный сбой: `503 → 503 → 503`, сообщение найдено в DLQ с requeue при просмотре;
- повторный POST возвращает тот же ID, изменённый payload с тем же ключом — 409.

Реальное отключение RabbitMQ: API принял новый платёж с 202; платёж оставался pending, Outbox — неопубликованным. После запуска RabbitMQ consumer автоматически доставил webhook.

Реальное отключение PostgreSQL: итоговый API вернул безопасный 503. После запуска БД API автоматически восстановил подключение и health вернулся к 200. Некорректный JSON с числом NaN возвращает 422.

Проверки выполнялись в локальном окружении. Секреты `.env`, содержимое баз данных, сообщения очередей, виртуальное окружение и кэши в репозиторий и Docker build context не включены.

## Воспроизведение

Инструкции запуска, curl-примеры и команды полного тестового Compose находятся в [README.md](README.md). Для повторения проверки HTTP используйте `.venv/bin/python scripts/smoke.py` после запуска профиля demo.

Проверки относятся к эмулятору платежей и локальному окружению. Они не подтверждают production HA, exactly-once или отсутствие повторного списания у реального внешнего платёжного провайдера.
